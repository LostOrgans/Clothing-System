# Clothing System

A digital wardrobe app. **v1 milestone: an Android avatar creator** — a stylized 3D
mannequin the user reshapes with sliders. Nothing else is in scope yet.

## What v1 does

- Renders a realistic parametric human with Filament.
- Sliders are generated at runtime from the model's 24 glTF morph targets. `*_min`/`*_max`
  pairs are combined into one slider per body dimension (0.5 = neutral).
- Six skin-tone presets change the mannequin's base colour live.
- An "Enter measurements" panel maps height, weight, chest, waist and hips to body shape;
  results are approximate and can be refined with the sliders.
- One-finger drag orbits, pinch zooms.
- Slider values persist across restarts (DataStore).

Explicitly **not** in v1: photo import, face mapping, clothes, outfits, recommendations,
accounts, backend, iOS.

## Architecture

See `docs/adr/0001-avatar-rendering.md`. Short version: Kotlin + Compose, Filament's
`ModelViewer` renders a GLB generated by `tools/make_avatar.py`. The GLB has three morph
targets; sliders set their weights through `RenderableManager.setMorphWeights`.

## Prerequisites

- Android Studio with Android SDK 35 and JDK 17
- Blender 4.x (only to generate the model, once)

## Build and run

1. Generate the avatar model. Install Blender 4.2+ and MPFB 2 as a Blender extension
   (from https://extensions.blender.org/add-ons/mpfb/), then:

   ```bash
   blender --background --python tools/make_avatar.py
   ```

   This writes `app/src/main/assets/models/avatar.glb`, a realistic human with 24 named
   morph targets covering gender, age, muscle, weight, proportions, height, cupsize and
   firmness plus MPFB detail targets. The app reads the target names from the GLB and
   creates one slider per target — no hard-coded slider list. MakeHuman assets are CC0.

2. Open the repository root in Android Studio. Let it download Gradle and the SDK.
   If there is no wrapper, use **File > New > New Project > Import** or run
   `gradle wrapper --gradle-version 8.9` once with a local Gradle install.

3. Run the `app` configuration on a device or emulator (API 24+).

If the model has not been generated, the app shows a message instead of crashing.

## Checks

```bash
gradle :app:compileDebugKotlin          # fast loop
gradle :app:testDebugUnitTest :app:assembleDebug   # full gate
```

## CI / APK

`.github/workflows/build-apk.yml` runs the full gate on pushes to `main`, pull requests,
and manual dispatch. It uses JDK 17 + Gradle 8.9 + Android SDK 35, builds a signed
`app-release.apk`, and uploads it as a workflow artifact.

On pushes to `main` (not pull requests) it also publishes a rolling **`latest` GitHub
Release** with the signed APK attached:
https://github.com/LostOrgans/Clothing-System/releases/tag/latest

The generated `avatar.glb` is committed so CI can bundle it into the APK. Regenerate it
with the Blender command above when the mesh changes.

## Controls

- Drag: orbit
- Pinch: zoom
- Sliders: reshape the mannequin; changes save automatically
