# 0001: Avatar rendering stack

- Status: Accepted
- Date: `2026-11-23`
- Deciders: repository owner

## Context

The first milestone is an on-screen 3D mannequin the user can reshape. The app is
Android-only and built by one person working part-time. A "parametric body" needs a mesh
whose vertices can be driven by sliders at runtime, not a static scan.

## Decision

Render a stylized low-poly humanoid GLB with Filament's `ModelViewer` helper
(`com.google.android.filament:filament-utils-android`). The GLB is generated by
`tools/make_avatar.py` in Blender and carries three morph targets: `Slim`, `Tall`,
`Muscular`. Compose sliders write those weights through
`RenderableManager.setMorphWeights`. Slider values persist in DataStore.

## Alternatives considered

| Alternative | Why not |
|---|---|
| Photogrammetry from many photos | Produces a static mesh that is hard to dress or animate; wrong tool for a wardrobe app |
| Hosted avatar service (e.g. Ready Player Me) | Cloud dependency, limited parametric control, no offline story |
| 2D paper doll | Cheaper, but the user explicitly chose a 3D parametric body |
| SceneView / custom OpenGL | More wrapper code than Filament's `ModelViewer` for the same result |

## Consequences

- Positive: free CC0 mesh pipeline, full control over shape keys, no backend, no licensing surprises.
- Negative: Filament/glTF plumbing is a learning curve; simple stylized look, not photoreal.
- Follow-up: photo-based face can later be mapped onto the same parametric body without
  replacing the renderer.
